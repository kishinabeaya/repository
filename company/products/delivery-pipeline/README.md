# デリバリー基盤 v0（受付から納品物の作成まで）

T-0030 / D-0022・D-0023。ホームページ・LPなどの依頼を、**Claude Codeが、受付票の整理から納品物の作成までを完結する**ための道具一式です。Python標準ライブラリだけで、パソコンの中だけで動きます。有料のツール、外部への送信、インストールは不要です。

## 1. CEOの作業と、Claude Codeの作業

| 工程 | ID | 担当（初期値） | 内容 |
|---|---|---|---|
| 受付 | intake | **CEO** | ココナラへのログイン、本人確認、規約の確認、依頼の受信、質問票の貼り付け |
| 要件確認 | requirements | Claude Code | 質問票の作成、顧客の返信の整理、欠けの検出、追加質問のまとめ |
| 制作 | build | Claude Code | サイトの生成、文章の調整 |
| 検証 | qa | Claude Code | 自動検査、レポート作成、目での確認 |
| 納品 | delivery | **CEO**（ZIPの作成はClaude Code） | 納品メッセージとZIPを、ココナラに転記・送付 |
| 修正対応 | revision | Claude Code（CEOは転記） | 修正の整理と実施 |
| 入金確認 | payment | **CEO** | 入金（売上確定）の確認 |

CEOが行うのは、ログイン、本人確認、規約の確認、承認、メッセージの転記、入金の確認だけ、が前提です（D-0023）。顧客の返信をClaude Codeに貼る作業も、CEOの作業（転記）として、時間を記録します。

## 2. CEOの使い方（プログラミングは不要）

Claude Codeに、次のように話しかけます。Claude Codeが、スクリプトを実行します。

1. 依頼が来たとき: 「**ホームページの依頼が来た。質問票を出して**」 → Claude Codeが質問票を出す。CEOは、それをココナラのメッセージに貼る。
2. 返信が来たとき: 「**返信を貼る。要件を整理して、足りないものがあれば、追加の質問を1通にまとめて**」 → 足りなければ追加質問が出る。CEOは、それを送る。
3. 要件がそろったとき: 「**ORD-0001を作って。検査して、納品用のZIPまで**」 → 生成・検査・ZIP・納品メッセージが出る。
4. 納品: 「**納品チェックリストを見せて**」 → CEOの項目（規約確認、転記、送付、入金確認）を実施する。
5. 修正の依頼が来たとき: 「**修正依頼を貼る。整理して直して、再検査して**」
6. 記録: 「**今回の工程の時間を記録して、CEOの割合を見せて**」

CEOの承認が必要なこと（D-0003）: 出品、価格の決定、公開、新しい種類の顧客向け文面。この基盤は、承認を代行しません。

## 3. 中身と、コマンド

すべて、このフォルダ（`company/products/delivery-pipeline/`）で実行します。

| 用途 | コマンド |
|---|---|
| 質問票を出す | `python3 intake/make_questionnaire.py homepage`（lp / automation / data） |
| 回答の欠けを調べる | `python3 intake/check_answers.py answers.json` |
| サイトを作る | `python3 scripts/build_site.py --answers answers.json --out site`（`--theme clean` か `warm`） |
| 検査する | `python3 scripts/qa_site.py site --report qa-report.md` |
| 納品物を作る | `python3 scripts/package_delivery.py --site site --answers answers.json --out out` |
| 工程を記録する | `python3 scripts/log_step.py --order ORD-0001 --step build --actor claude --minutes 25 --note "LPを生成"` |
| CEOの割合を見る | `python3 scripts/report_share.py` |
| テスト | `python3 -m unittest discover -s tests` |

- **intake/**: 質問票（共通 + 領域別。氏名・連絡先・住所は聞かない）、`answers_template.json`（回答の入れ物）、`check_answers.py`。回答は**JSON**（標準ライブラリで読める）。顧客の自由な文章の返信は、Claude Codeが、この形に書き起こします。
- **templates/**: 制作のひな形。`theme-clean.css`（青系）、`theme-warm.css`（茶系）、`base.css`、`page.html`。
- **scripts/**: `build_site.py`、`qa_site.py`、`package_delivery.py`、`log_step.py`、`report_share.py`、共通部品。
- **samples/**: サンプル作品3点（bakery、spreadsheet-lp、garden）。各フォルダに、回答、生成したサイト、検査レポート。全ページの上部と下部に「サンプル（架空の事業者）」と表示。
- **tracking/steps.jsonl**: 工程の記録（初期は空）。
- **tests/**: unittest。

### 工程の記録の形式
1行1件のJSON: `{"order_id","step","actor","minutes","note"}`。actor は `claude` か `ceo`。order_id は英数字（個人名を使わない）。note に、メール・電話・郵便番号らしき文字があると、記録を拒否します（氏名は機械で見分けられないため、書かないでください）。

### 割合の計算
- **時間ベース（目標の判定に使う）:** CEOの分 ÷ 全体の分。目標は10%以下。
- **工程ベース（参考）:** (注文, 工程, 担当) の組を1件と数え、CEOの件数 ÷ 全件数。CEOの工程（受付・納品・入金確認）は、時間が短くても件数では割合が高く出ます。見るべきは、CEOの記録が、転記・確認・承認・入金確認に限られているか、です。

## 4. 検査でわかること（qa_site.py）
HTML構文の基本（閉じ忘れ、対応しないタグ、id重複）、`lang`・`title`・文字コード・`viewport`、見出し（h1は1つ、階層の飛びなし）、画像の`alt`、内部リンク切れ（ファイルと`#`アンカー）、CSSの色のコントラスト比（WCAG、4.5:1。`#rgb`/`#rrggbb`/`var()`に対応）、ファイルサイズ（HTML 100KB、CSS 60KB、全体300KB以下）、外部読み込み（注意として表示）、禁止・誇大表現（「必ず」「絶対」「No.1」「業界最安」「今すぐ」「限定」、根拠が要る「受賞」「お客様の声」「累計」など）。不合格だと、ZIPを作りません。根拠がある語は `--allow 語` で、人が許可できます。

## 5. 限界（できないこと）
- **ココナラとのやり取りは、すべてCEOの転記です。** APIがなく、Claude Codeは、メッセージの受信も送信も、ログインもできません。やり取りの往復は、減らす設計ですが、ゼロにはなりません。
- **確認できないこと:** 文章が事実と合っているか、法令（景品表示法・特定商取引法など）に適合しているか、見た目の良し悪しは、機械では判断できません。禁止表現の検査は、文字の検索だけです。言い換えて通り抜ける表現は、検出できません。弁護士の確認は受けていません。
- **作れるもの:** 静的なHTML/CSSのサイト（ホームページ3ページ、またはLP1ページ）。フォーム送信、会員機能、ECの決済、CMS、データベースは、できません。外部サービスは使いません。
- **画像・写真・ロゴ・独自フォント:** 扱いません（顧客提供の素材の取り込みは、v0にありません）。文章と簡単な図形のデザインです。
- **業務自動化・データ集計:** 受付票と欠けの検査までです。スクリプトの雛形・検査・納品のパッケージ化は、v1の課題です。ECサイト構築も、v0の対象外です。
- **ブラウザでの実機表示の確認は、していません。** スマホ表示は、viewportとレスポンシブCSSの有無までの検査です。見た目は、ブラウザで開いて確認してください。
- 「Claude Codeが9割」は、記録された時間の比率です。実際の受注・納品で測るまで、達成は未検証です。このv0は、サンプルでの動作確認だけです。
- 受注できる見込みや、顧客がAIを自分で使う代替の影響は、この基盤では分かりません（調査資料: `company/knowledge/research/2026-11-proven-sellers/claude-code-candidates.md`）。
- ココナラのAI作成物の規約は未確認です。出品前に、CEOが公式情報で確認してください。

## 6. 提供原則との対応
- AI補助の明示: 質問票の冒頭と、納品の説明（README・納品メッセージ）に、「制作にAI（Claude Code）を補助として使い、人が確認する」と入れています。サイトのフッターへの表示は、`show_ai_note` で選べます。
- 虚偽の実績・口コミ・肩書きを入れない: ひな形に、そのような欄はありません。サンプルは「サンプル（架空の事業者）」と明記し、実在の事業者と混同しない名前にしています。
- 個人情報を集めない: 質問票は、氏名・連絡先・住所を聞きません。回答に紛れ込んだ場合は検出します。

## 7. 素材の出典・ライセンス
文章・CSS・HTMLのひな形は、すべて新規に作成しました。外部の画像・フォント・ライブラリは、使っていません。
