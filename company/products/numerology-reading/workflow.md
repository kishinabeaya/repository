# 鑑定の進め方（CEO向け手順書）

対象: 入口鑑定（約1,000字・500円）、標準鑑定（約2,000字・2,000円）、入口へのオプション（相談1問／月ごとのヒント）。星座×数秘の鑑定です。プログラミングの知識は不要です。
時間の目安（推定。実測で更新）: 入口 15〜20分、標準 25〜40分、オプションは各+5〜10分（推定）。品質優先で超えてよい（D-0008）。
前提（始める前に必ず確認）:
- ココナラの出品・価格はCEO承認済みであること（D-0003）。このキットは出品そのものは含みません。
- 依頼者情報（呼び名・生年月日・相談要旨）を外部のAIに入力してよいか（ココナラの規約・プライバシーの取扱い）を、CEOが出品前に画面で確認すること。不可の場合は、氏名・呼び名を伏せ、生年月日（と星座・数の計算結果）だけでAIに下書きさせ、呼び名や相談への回答は自分で書き足す。確認前は鑑定を始めない。

## 0. 初回だけの準備（約10分）
1. ターミナルを開き、このキットの `scripts` フォルダに移動する（フォルダの場所は環境ごとに違うため、Claude Codeに「numerology-reading の scripts フォルダに移動するコマンドを教えて」と聞いてもよい）。リポジトリ内の `company/products/numerology-reading/scripts` が目的地。
2. テストを実行して動作を確認する。`python3 test_numerology.py` と `python3 test_check_text.py` の最後に `OK` と出ればよい。
3. 下書き置き場を作る（ファイルが増えても個人情報を残さないため、保存先はリポジトリ外に）。
   `mkdir -p ~/drafts`
   重要: 依頼者の氏名や相談文はリポジトリ内に保存しない（コミットされるため）。

## 1. 依頼の受付（約2分）
1. ココナラのメッセージ（購入前の質問）で、依頼者の「生年月日」「呼び名」「相談内容（標準、または相談オプションのみ）」と、購入されたオプションの有無を確認する。
   不足なら、ココナラ上で丁寧に聞く（外部の連絡先は聞かない・教えない。外部取引は禁止）。
2. 重い悩み（自傷・命に関わる内容・病気・借金・DV など）が書かれていたら、鑑定を作らず `templates/disclaimer.md` の定型返信（公的な相談窓口の案内つき）を送る。購入後のキャンセル手続きは、出品前に画面で確認した方法で行う。不倫の成就・縁切りなどの依頼もお断りする。
3. 氏名・住所などは AI に渡さない。AI に渡すのは「呼び名・生年月日・相談要旨」だけ。

## 2. 数の計算（約1分）
1. 次を実行（日付を差し替える）。
   `python3 numerology.py 1992-07-23`
   名前（ローマ字）の提供があり標準鑑定で使うなら `--name "Hanako Yamada"` を付ける。
2. 出力の例:
   ```
   ライフパスナンバー: 6
   誕生数: 5
   太陽星座: 獅子座  ※境目の日です。蟹座か獅子座のどちらか、依頼者に確認してから書く
   2027年の個人年数(パーソナルイヤー): 5（その年の全体の数: 2）
   月ごとの数: 1月=6 2月=7 ...
   ```
3. 「境目の日です」と出たら、ココナラ上で依頼者に「ご自身の星座はどちらですか」と聞き、答えた星座で書く（返事を待つ間は納期に注意）。
   「別流派では○○」と出たときは、標準鑑定では注記を入れ、入口鑑定では採用方式（A）のままで書く。
4. 気になるときは電卓や手計算で1回確かめる（計算の考え方は spec.md 参照）。

## 3. AI（Claude Code）で下書きを作る（約3分）
1. Claude Code を開く。`templates/` の entry-reading.md（標準なら standard-reading.md。オプションは option-consult.md、option-monthly.md）、number-keywords.md、disclaimer.md を読めるようにしておく（同じセッションで場所を伝えればよい）。
2. 下の「依頼文の例」の `〇〇` を埋めて、そのまま貼り付ける。
3. 出てきた下書きを `~/drafts/001.txt` のように連番の名前で保存する（コピーして貼り付けるだけでよい。ファイル名に呼び名を入れない）。

### 依頼文の例（入口鑑定）
```
company/products/numerology-reading/templates/ の entry-reading.md を型にして、数秘術の入口鑑定の下書きを作ってください。
参考資料は同じフォルダの number-keywords.md と disclaimer.md です。

【依頼者】呼び名: 〇〇さん
【生年月日】1992-07-23
【太陽星座】獅子座（境目の日の場合は、依頼者に確認した星座）
【計算結果（スクリプト出力。この数字を変えないこと）】
ライフパスナンバー 6 / 誕生数 5 / 2027年のパーソナルイヤー 5 / 2027年全体の数 2
【相談内容】（なければ「特になし」）〇〇

【ルール】
- 約1,000字。数秘と星座を重ねて書く。行動ヒントは3つ。天体の動き（水星逆行・新月満月）は書かない。「〜な傾向があると言われます」「〜してみるのもよいかもしれません」の語尾。
- 断定、不安をあおる表現、医療・投資・退職・離婚などの判断、霊視・除霊などの表現は使わない。
- 見出しは「■」を使い、Markdown記号（#、*、---）は使わない。
- 末尾に disclaimer.md の「この鑑定について」「制作について」をそのまま入れる。
- 数字は上の計算結果だけを使い、自分で計算し直さない。
- 他の鑑定文の流用や、実在しない実績の記載をしない。
出力は鑑定文の本文だけにしてください。
```

### 依頼文の例（標準鑑定。入口との差分）
上の文のうち、最初の行を「standard-reading.md を型にして、標準鑑定（約2,000字、月ごとのヒントと相談1問への回答つき）」に変え、次を足す。
```
【月ごとの数】1月=6 2月=7 3月=8 4月=9 5月=1 6月=2 7月=3 8月=4 9月=5 10月=6 11月=7 12月=8
【名前の数（任意）】表現数 〇 / ソウル数 〇   ← 提供がなければ「なし」
【相談の要旨】（個人が特定される情報は除いて短く）〇〇
相談への回答（option-consult.md の形）は、数秘術の視点からの考え方のヒントにとどめ、決断を促さないこと。
```

### 依頼文の例（入口へのオプション）
入口の依頼文の最後に、購入されたオプションに応じて足す。
```
【オプション】月ごとのヒントあり → option-monthly.md の形で、上の月ごとの数を使って12か月分を各30〜40字で書く
【オプション】相談1問あり → option-consult.md の形で約300字。相談の要旨: 〇〇
```

## 4. 禁止語のチェック（約1分）
`python3 check_text.py ~/drafts/001.txt`
- 外部への誘導の語（http、@、QR、LINE、note、DM、直接、外部、連絡先など）も検索します。ヒットは必ず直す（「直接」などは文脈で無害なこともあるので読んで判断）。
- 「禁止語のヒットなし」ならOK。ヒットしたら該当行を言い換える（言い換え例は 2026-11-fastest-revenue-plan.md の7章）。
- 数が合っているか、出力と照らして確認する。

## 5. CEOの確認・手直し（入口 約8分 / 標準 約15分以上。時間をかけてよい）
AIの文章をそのまま送らない。次の観点で読み、自分の言葉に直す。
1. 依頼者の名前・生年月日・相談内容に合っているか（取り違え防止）
2. 数の値がスクリプトの出力と同じか
3. 星座の良し悪しをつけていないか。言い切りや脅しに読める箇所はないか（check_text.py では見つからない表現もある）
4. 相談に答えているか。一般論だけになっていないか
5. 最後に1〜2か所、自分の言葉で一言を足す（これが品質と満足度を決める）
6. 免責文とAI利用の開示の文が末尾に残っているか
7. 見出しが「■」で、ココナラの納品画面に貼ったとき記号が崩れていないか（初回は貼り付け後の表示を確認）

## 6. 納品（約2分）
1. 完成文をココナラの納品画面（またはメッセージ）に貼り付けて送る。
2. 外部サイト・SNS・連絡先への誘導を入れない。追加購入を勧めない。
3. 送ったあと、`~/drafts/` の該当ファイルを削除する（個人情報を残さない）。
4. 記録として、次の4項目だけを company/logs 以外の自分用メモ（またはCoSへの共有）に残すとよい: 受付日、種類（入口/標準/オプションの有無）、かかった時間（初回3件は特に実測して記録）、AI下書きの手直し量（多い/普通/少ない）。依頼者の氏名・相談内容は書かない。
5. 初回3件は、個人情報を除いた形で Analyst の品質レビューを受ける（運用ルール）。

## よくあるつまずき
- `python3: command not found` → `python` で試す。それでもだめなら Claude Code に「Pythonのバージョンを確認して」と頼む。
- 日付のエラー → `YYYY-MM-DD`（例: 1992-07-23）で、実在する日付を入力。
- AIが数を勝手に変えた → 依頼文の「この数字を変えないこと」を強調して再依頼。
