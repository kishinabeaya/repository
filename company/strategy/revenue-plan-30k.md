# 月3万円チーム 実行計画（D-0021）

作成: CoS 2026-11-21。**根拠の区別:** 【実績】観測データ／【計算】観測データからの算術／【仮定】未検証の前提／【設計】当社の判断。

## 1. 目標の定義
- **月3万円（手取り）** = 販売先の手数料を引いた後の金額（【仮定】CEOに確認中）。
- 最初の期限: 2026-11-30 に1件以上を公開（KR2）、2026-12-15 に初売上（KR3）。**月3万円のペース到達は、公開後の実績で判断し、日付を約束しない**（初受注までの日数の公式データがないため）。

## 2. 目標から逆算した必要量（【計算】。観測した価格を使う）
手数料率は、ココナラの電話・テキストで未確認のため、**22%と仮定**（【仮定】テキスト・ビデオの22%を電話にも適用。出品時の画面で、CEOが確認する）。

| ライン | 単価 | 手取り（22%引き） | 月3万円に必要な量 |
|---|---|---|---|
| 話し相手（電話・分単価）【実績: 分単価の中央値100円（47件中27件）】 | 100円/分 | 78円/分 | **約385分（約6.4時間）/月**（約1.5時間/週） |
| 話し相手 | 120円/分 | 93.6円/分 | 約321分（約5.3時間）/月 |
| AI占いレポート（価格はCEOが決定。例） | 1,000円 | 780円 | 約39件/月 |
| AI占いレポート（例） | 3,000円 | 2,340円 | 約13件/月 |

- 【実績】話し相手の上位サービスのリピートを示す語は、レビューの25.2%。ただし、新規が最初の評価を得る日数は【実績】の範囲で、評価の1件目から10件目まで中央値51日（話し相手、n=7、生き残った出品者のみ）。**したがって、最初の1〜2か月は、必要量に届かない可能性が高い。**
- **ボトルネックは作業量ではなく、集客（買い手に見つけてもらうこと）。** v3・T-0020の調査と同じ結論。

## 3. チームと役割
| 役割 | 担当 | 仕事 |
|---|---|---|
| 責任者・PDCA | CoS | 毎日の進行、毎週の振り返りと改善、CEOへの許可の依頼 |
| ライン1「話し相手」 | CEO（電話に出る）／creator（出品文・運用ルール）／analyst（記録・集計） | 出品、受電、記録。**AIは通話に出ない**（D-0020）。AIは準備と記録の補助のみ |
| ライン2「AI占いレポート」 | creator（文面）／builder（生成の手順・スクリプト）／CEO（表現と安全面の確認・お届け） | 注文から納品まで。AIが作ることを明示 |
| 集客 | marketer／creator | Threads（占い・自己理解用）、MBTI系アカウントのリポスト（D-0019）、ココナラ内の検索対策 |
| 計測・改善 | analyst | 指標の集計、週次の判定、出典の確認 |
| 承認・実行 | CEO | ログイン、出品、投稿、受電、本人確認、許可（A-0004） |

## 4. PDCAの回し方
- **P（計画）:** 毎週月曜。CoSとanalystが、前週の数字で、その週の施策を最大3つに絞る。
- **D（実行）:** 毎日 `/daily`。AI社員が準備し、CEOがログインを伴う作業を行う。
- **C（確認）:** 毎週金曜か土曜、`/weekly`。指標を kpi.csv に記録し、事前の判定基準で、うまくいった／いかなかった／不明、を判定する。
- **A（改善）:** 判定に従い、1つだけ変えて、次の週に回す（一度に複数を変えない）。結果を lessons.md に記録する。

### 毎週記録する指標（company/metrics/kpi.csv）
公開サービス数／ココナラの表示回数・お気に入り数（出品画面の数字）／問い合わせ数／受注件数／販売分数（話し相手）／売上（手取り）／CEOの作業時間／Threadsの投稿数・インプレッション・返信数・プロフィールへの訪問（取れる範囲）／経費（0円のはず）。

### 事前に決めておく判定基準（【設計】。予測ではなく、行動を決めるための基準）
| 公開後の経過 | 状況 | 次の行動 |
|---|---|---|
| 7日 | 表示回数が極端に少ない（出品画面で確認） | タイトル・サムネイル・カテゴリを1回見直す |
| 14日 | 受注0件 | 価格かタイトルを1つだけ変えてさらに14日 |
| 28日 | 受注0件 | そのラインを一時停止。T-0025等の観測データに基づき、別のラインへ（CEOに報告し、承認を取る） |
| 28日 | 受注あり | 受注の理由（購入者のメッセージ・レビュー）を記録し、同じ型を増やす |
| 随時 | 提供原則に反する問題（苦情、規約違反の警告） | 直ちに該当の出品を止め、CEOに報告 |

## 5. 許可が必要なもの（D-0021。承認依頼 A-0004）
| 項目 | 区分 | 内容 |
|---|---|---|
| ココナラの出品者登録・本人確認・出品作業 | ログイン・個人情報 | CEO本人が行う。AIはログインしない |
| Threadsの投稿、MBTI系アカウントのリポスト | ログイン | CEO本人が行う。投稿は事前承認（D-0003） |
| 顧客の生年月日などを、AI（Claude）に入力して鑑定レポートを作ること | 個人情報の開示 | 氏名を含めず、生年月日と相談内容だけを入力する案。ココナラの規約・プライバシーの確認が必要 |
| 経費 | 経費 | 現時点は0円の想定。発生する場合は、都度、承認依頼を出す（例: 有料ツール、広告） |

## 6. 最初の2週間のスケジュール（【設計】。日付は目標）
| 期間 | 内容 |
|---|---|
| 11/21〜11/22 | 承認依頼 A-0004 を出す。出品文（話し相手、AI占いレポート）、運用ルール、Threads投稿の下書きを作る |
| 11/23〜11/25 | Analystが下書きを確認。CEOが内容を承認・修正 |
| 11/26〜11/28 | CEOがココナラの規約を画面で確認し、出品（本人確認がまだなら先に手続き） |
| 11/29〜 | 公開後の毎日・毎週のPDCA。Threadsの投稿を開始 |

## 7. 守ること
- 提供原則（service-principles.md）、根拠の基準（D-0018）、AIの開示（D-0007、D-0020）。
- 話し相手は、CEO本人が対応する。AIが人を装って対応しない。深刻な声（命や安全に関わる内容）が出た場合は、公的な相談窓口を案内する。利用の上限と、終わらせやすさを、出品文と運用ルールに明記する。
- 「AI占い副業」のノウハウ販売はしない（D-0020）。
